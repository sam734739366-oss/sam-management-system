# خطة تنفيذ V4 — نظام SAM

> **للتنفيذ الآلي:** كل مهمة في هذه الخطة تُنفَّذ بالترتيب. صُمِّمت لتُنفَّذ في جلسة واحدة مع فحوصات بين المراحل.

**الهدف:** إصدار v0.4.0 يضيف طبقة المستندات الحركية، ويحوّل مركز التقارير إلى نافذة منبثقة، ويعيد تصميم الإدخال الذكي والطباعة والهوية البصرية — دون فقدان أي بيانات قائمة.

**المعمارية:** دفتر `stock_moves` يبقى مصدر الحقيقة الوحيد؛ كل مستند جديد (سند استلام الإنتاج، إذن إدخال، إذن خروج، تسوية جرد) يعيش في جدول `documents`؛ الأرصدة مشتقة ⇒ الحذف والتعديل يعكسان الأثر فعليًا بلا كود عكسي.

**التقنيات:** Electron 33 · better-sqlite3 · Vanilla JS (renderer) · exceljs · electron-updater.

**التصميم:** `docs/superpowers/specs/2026-11-10-sam-v4-design.md`

## القيود العامة (كل مهمة تراعيها)

- لا تُحذف بيانات مستخدم أبدًا: كل ترحيل **إضافة فقط** (عمود/جدول/عَلَم).
- لا قيم افتراضية في حقول الإدخال (اسم/صنف/مخزن) — فقط تاريخ اليوم في حقول التاريخ.
- كل عملية DB جديدة تحتاج **سطرين**: `API[name]` و `PERMS[name]` في `src/main/ipc-db.js`، وتصديرها من `src/main/db.js`.
- `stock_moves.bucket` يقبل `good|defect` فقط بعد الترحيل.
- الكمية الأساسية = الحبة؛ الكرتونة والكيس معلوماتيان.
- كل رد على المستخدم بالعربية.
- لا commits ولا رفع لـ GitHub إلا بأمر صريح من المستخدم.

## المرحلة 1 — طبقة البيانات (`src/main/db.js`)

### المهمة 1: توسيع أنواع المستندات + إيقاف أثر تقرير الإنتاج + إعادة تصنيف «محرز»

**الملفات:** `src/main/db.js`

**خطوات:**
1. أضف إلى `DOC_KINDS`: `prod_receipt` (+1), `gate_in` (+1), `gate_out` (−1), `adjustment` (0 → sign من `meta`).
2. أضف دالة `rebuildDocumentsTable()` داخل `migrate()`:
   - `PRAGMA foreign_keys=OFF`
   - إنشاء `documents_new` بنفس بنية `documents` مع CHECK موسَّع
   - `INSERT INTO documents_new SELECT * FROM documents`
   - `DROP TABLE documents` + `ALTER TABLE documents_new RENAME TO documents`
   - إعادة إنشاء الفهارس
   - `PRAGMA foreign_keys=ON` + `PRAGMA foreign_key_check`
3. أضف `reBucketHeld()`: مرة واحدة خلف عَلَم `meta.buckets_merged_held` — `UPDATE stock_moves/doc_lines SET bucket='defect' WHERE bucket='held'`.
4. عدّل `BUCKETS` إلى `['good','defect']` و `AR_BUCKET` accordingly (اترك `held` في AR_BUCKET للقراءة التاريخية فقط).
5. عدّل `saveReceipt`: أوقف إنشاء `stock_moves` (لا أثر على المخزون) — يبقي كتابة `prod_receipts`/`prod_receipt_lines` فقط.
6. عدّل `saveDocument` ليدعم الأنواع الجديدة و`adjustment` أخذ `meta.deltaSign`.
7. `migrate()` ترتيب: reBucketHeld بعد rebuildDocuments.

**التحقق:** شغّل `node tools/test-db.js` + `node tools/v3-db-check.js` على نسخة؛ تأكد من `foreign_key_check` فارغ ومن عدم تغيّر عدد الحركات.

### المهمة 2: استعلامات التقارير الجاهزة

**الملفات:** `src/main/db.js`

**خطوات:**
1. وسّع `reportQuery(filters)` بمعامل `report` يقبل: `stock_status | movement_summary | item_ledger | warehouse_flow | shortage | damage | party_balance`.
2. لكل تقرير: SQL مستقل داخل `reportQuery` عبر `switch` يعيد `{ rows, columns, totals, ... }` بنفس شكل الاستجابة الحالي حتى لا تنهار الواجهة.
3. `dailyReport(filters)` يبقى كما هو + تقرير `production_gap` جديد يعيد العجز/الزيادة من `prod_receipt_lines`.
4. صدّر `reportRun` كغلاف: `reportRun(filters)` → `reportQuery(filters)`.

**التحقق:** `node tools/v3-db-check.js` يطبع نتائج التقارير الستة على قاعدة الاختبار.

## المرحلة 2 — الجسر والطباعة (main)

### المهمة 3: `ipc-db.js` — API + PERMS

**الملفات:** `src/main/ipc-db.js`

**خطوات:**
1. أضف إلى `API`: `reportRun`, `prodReceiptSave`, `prodGapReport`, `dataDirInfo`, `dataDirPick`, `syncCloud`, `printerList`, `dbBackupNow`.
2. أضف إلى `PERMS` القواعد المقابلة (شاشة + فعل).
3. أضف `preload.js`: `sam.db.invoke` موجود مسبقًا — يكفي. أضف `sam.print.printers()` و `sam.print.print(opts)` wrappers.

### المهمة 4: `ipc.js` — إصلاح الطباعة + قائمة الطابعات

**الملفات:** `src/main/ipc.js`

**خطوات:**
1. `win:print`: احذف `pageSize` المخصص و `margins` المخصصة ⇒ `webContents.print({ silent:false, printBackground:true, copies:1, deviceName })`. أرجع `{ ok, error, failureReason }`.
2. أضف `win:printers`: `w.webContents.getPrinters()` ⇒ `[{name, isDefault, status}]`.
3. `win:savePdf`: أبقِ `printToPDF` مع `printBackground:true`، صفحة A4، هوامش `0.2` إنش، وأضف `preferCSSPageSize:true`.

### المهمة 5: `xlsx.js` — إصلاح الطباعة الباهتة

**الملفات:** `src/main/xlsx.js`

**خطوات:**
1. `pageSetup`: `fitToPage:true, fitToWidth:1, fitToHeight:0, horizontalCentered:true`, هوامش 0.25/0.4.
2. `ws.pageSetup.printTitlesRow = '1:1'`.
3. كبّر الخطوط: عنوان 18، عناوين أعمدة 12 غامق، نص 11.5.
4. `ws.views` RTL مضبوط + `alignment.readingOrder='rtl'` لكل خلية.

### المهمة 6: `backup.js` — مجلد البيانات + المزامنة بالبريد

**الملفات:** `src/main/backup.js`, `src/main/db.js`

**خطوات:**
1. `db.dataDir()` يقرأ `process.env.SAM_DATA_DIR` ثم إعداد `data.dir` ثم الافتراضي.
2. `backup.js`: `dataDirInfo()`, `pickDataDir()` (نقل آمن: نسخ + إبقاء الأصل)، `syncCloud({email, folder, auto})`، `cloudSyncNow()`.
3. كشف المزوّد من البريد: `gmail.com → google`, `outlook|hotmail → microsoft`, غير ذلك → generic.
4. كتابة `sam-<stamp>.db` في `<folder>/SAM-Backups/` + `sync.log` + حصر 12 نسخة.

### المهمة 7: `updater.js` — نسخة احتياطية قبل التحديث

**الملفات:** `src/main/updater.js`

**خطوات:** في `update:install` قبل `quitAndInstall` → `require('./backup').backupNow('pre-update')`.

## المرحلة 3 — الواجهة

### المهمة 8: `combobox.js` — إعادة تصميم الإدخال الذكي

**الملفات:** `src/renderer/js/combobox.js`, `src/renderer/css/theme.css`

**خطوات:**
1. caret ⇒ `<button type="button" class="combo-caret">` يبدّل القائمة (يعمل بحقل فارغ وبعد اختيار).
2. `+` ⇒ `<button class="combo-plus">` بأيقونة SVG.
3. تخطيط: `.combo-field{display:grid;grid-template-columns:1fr auto auto;gap:6px;align-items:center}` — لا تراكب.
4. زر «تغيير» يظهر بعد الاختيار ⇒ يفتح القائمة على نفس الحقل.
5. `filtered()`: عند الفتح بدون كتابة ⇒ أظهر الكل (سلوك موجود) — الفتح نفسه مسموح دائمًا.

### المهمة 9: `ui.js` — أيقونات الحقول + معاينة A4 + رسائل الطباعة

**الملفات:** `src/renderer/js/ui.js`

**خطوات:**
1. `field(label, node, hint, iconName)` — أيقونة SVG ثابتة قبل النص.
2. `printPreview`: شريط أدوات فيه «الطابعة: <select>»، و«تصدير PDF»، و«طباعة».
3. رسالة خطأ الطباعة المفصّلة.

### المهمة 10: `documents.js` — هوية المستندات + شبكة اختيار النوع + إزالة الافتراضيات

**الملفات:** `src/renderer/js/documents.js`, `src/renderer/css/app.css`, `src/renderer/css/theme.css`

**خطوات:**
1. `KIND_STYLE` لكل نوع (لون/أيقونة/تسمية/وصف).
2. نافذة «اختيار نوع المستند» = شبكة بطاقات.
3. ترويسة المستند الملوّنة + شريط بأيقونة النوع.
4. إزالة كل القيم الافتراضية من `defaultCell` (المخزن، الصنف، التاريخ).
5. عمود الصنف بعرض مرن عبر `<colgroup>`.
6. `permitPages` يشمل الأنواع الجديدة.

### المهمة 11: `production.js` — سند استلام الإنتاج + قسم العجز

**الملفات:** `src/renderer/js/production.js`

**خطوات:**
1. تبويب «سند استلام الإنتاج» ⇒ محرر مستند بنمط `prod_receipt` (مخزن لكل سطر، لا افتراضي).
2. بعد الحفظ ⇒ زر «طباعة تصريح الخروج» ⇒ `permitPages` للنوع الجديد.
3. تبويب «العجز والتالف» ⇒ جدول تقرير الإنتاج اليومي + تقرير مطبوع + Excel (بلا أثر على المخزون).
4. إزالة شارة «محرز».

### المهمة 12: `reports.js` + `daily.js` — مركز التقارير كنافذة

**الملفات:** `src/renderer/js/reports.js`, `src/renderer/js/daily.js`, `src/renderer/css/app.css`

**خطوات:**
1. `run()` ⇒ overlay: فلاتر + قائمة تقارير جاهزة + معاينة + أزرار (Excel/PDF/طباعة/إغلاق).
2. دبل-كليك على البند ⇒ فتح مصدره (فاتورة/سند) + تعديل/حذف مع تحذير الأثر.
3. Reports الجاهزة: أرصدة، حركة، كشف صنف، تدفق مخازن، نقص، تالف، حساب أطراف، إنتاج.
4. `daily.js` ⇒ نفس النافذة.

### المهمة 13: `settings.js` + `app.js` + `app.html` — الأيقونات والمزامنة والدليل

**الملفات:** `src/renderer/js/settings.js`, `src/renderer/js/app.js`, `src/renderer/app.html`, `src/renderer/css/theme.css`

**خطوات:**
1. أيقونات SVG جديدة في `app.html`: `i-user, i-calendar, i-hash, i-money, i-tag, i-list, i-warehouse, i-scale, i-out, i-in, i-help`.
2. زر التحديث في شريط العنوان ⇒ نافذة التحديث (تستخدم `sam.update`).
3. الإعدادات: اختيار مجلد البيانات + المزامنة بالبريد + دليل الاستخدام.
4. دليل الاستخدام: نافذة `?` بمحتوى عربي.
5. إزالة «محرز» من `app.js` و`daily.js` و`items.js` و`reports.js` و`documents.js`.

## المرحلة 4 — الفحص والنشر

### المهمة 14: فحوصات
1. نسخة من قاعدة بيانات العميل ⇒ ترحيل ⇒ تحقق (لا حركة ضائعة، أرصدة مطابقة، `foreign_key_check` فارغ، `integrity_check` ok).
2. `node tools/test-db.js` و `node tools/v3-db-check.js`.
3. لقطة شاشة لكل شاشة جديدة عبر `tools/shot*.js` للتحقق البصري.
4. `npm run rebuild:native`.

### المهمة 15: النشر
1. تحديث `package.json` إلى 0.4.0.
2. commit + push (بأمر المستخدم).
3. GitHub Actions يبني وينشر v0.4.0.
4. التحقق من الأصول الـ4 + sha512.
5. إرسال الرابط المباشر للتحديث.
